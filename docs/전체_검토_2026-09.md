## 이번에 고친 것

### 하원 체크표가 느렸습니다 — 1,973ms → 713ms

화면마다 서버 응답 시간을 실제로 재봤습니다.

```
하원 체크표   1,973ms   ← 다른 화면의 두 배
학생 조회     1,168ms
셔틀 개요     1,159ms
업무 보드       949ms
인보이스        453ms
운영 대시보드   421ms
```

체크표는 자료를 **열네 번** 읽는데 그것을 **한 줄씩 차례로** 기다리고 있었습니다.
서로의 결과를 쓰지 않는 여덟 개를 한꺼번에 보내도록 바꿨더니 **713ms**(가장 빠를 때
588ms)가 됐습니다. 하루에 가장 많이 여는 화면이라 이 차이가 그대로 쌓입니다.

**남은 것**: 학생 조회(1,168ms)와 셔틀 개요(1,159ms)도 같은 구조입니다. 다음에 같은
방식으로 줄일 수 있습니다.

## 남아 있는 약한 자리

### 1. 이름 대조가 여섯 곳에 흩어져 있습니다 🔴

`attendanceDigest` · `attendanceIntent` · `pickupParse` · `pickupIngest` · `rideAlong` ·
`passportPhoto` — **여섯 파일이 각자 이름을 맞춥니다.**

이번 주에 난 오류들이 전부 여기서 나왔습니다.

| 언제 | 무엇 | 어디서 |
|---|---|---|
| 사진 | `고서윤` 이 안 맞음 (맥의 자모 분리) | passportPhoto |
| 출결 | `이예나 셔틀 안탑니다` 통째로 무시 | attendanceDigest |
| 동승 | `하임이` → 임하임·정하임 못 가림 | rideAlong |
| 문의 | `김재이` 셋 중 누구인지 표시 안 됨 | pickupParse |

**한 곳을 고쳐도 나머지 다섯은 그대로입니다.** 부서 판정(`departmentOf`)을 한 곳으로
모으고 검사기를 붙였던 것과 같은 문제인데, 이름 대조는 아직 안 모았습니다.

→ **제안**: `src/lib/studentName.ts` 하나로 모으고 `check-studentname.mjs` 로 다른 곳에서
못 만들게 막습니다. 규모 2~3일.

### 2. 필요 없는 칸까지 읽는 조회가 200곳

`select("*")` 가 200곳입니다. 그중 170곳은 **개수 제한도 없습니다.** 지금은 자료가
적어 티가 안 나지만, 관찰기록이 쌓이면 그때부터 느려집니다. 그리고 없는 칸 하나 때문에
화면 전체가 비는 사고(이번 `mother_phone`)도 여기서 납니다.

→ 자주 여는 화면(체크표·업무·학생)부터 필요한 칸만 적습니다. 규모 1~2일.

### 3. SQL 을 손으로 돌리고 계십니다

마이그레이션이 79개인데, 실행은 사람이 화면에서 붙여넣습니다. 그래서 지금도
`stamp_current_term()` 이 없는 상태입니다 — **어느 것이 돌아갔는지 아무도 모릅니다.**

GitHub Actions 워크플로(`supabase-migrate.yml`)가 이미 있는데 쓰이지 않고 있습니다.

→ 이것부터 살리는 것을 권합니다. 지금은 "어느 SQL 이 실행됐나"가 사람 기억에만 있습니다.

## 국제학교 통합운영앱 — 더 넣을 것

지금 없는 것 중에서, **이 학교에서 실제로 아쉬울 것**만 골랐습니다.

### A. 지금 당장 값어치가 큰 것

#### A-1. 출결을 학생 기준으로 쌓기 (출석부) 🔴

지금 출결은 **셔틀을 위한 것**입니다. 오늘 누가 결석인지는 알지만,
**"김서이가 이번 학기에 며칠 결석했나"** 를 물으면 답이 없습니다.

국제학교는 이 숫자가 필요한 자리가 많습니다 — 상급학교 서류, 비자·체류 관련 증빙,
학부모 상담, 출석 일수 규정.

이미 `attendance_entries` 에 자료가 쌓이고 있어서 **화면만 만들면 됩니다.**
학생별 월/학기 집계와 출석부 인쇄. 규모 2~3일.

#### A-2. 학생 서류 만료 관리

국제학교라 여권·비자·재학증명·건강기록이 **만료됩니다.** 지금은 어디에도 없습니다.
만료 30일 전에 업무로 올라오게 하면, 그날 급하게 찾는 일이 없어집니다. 규모 2일.

#### A-3. 상담 기록 (학부모 면담)

관찰기록은 있지만 **면담 기록**이 없습니다. 언제 누가 무엇을 이야기했는지가 남지 않아
담임이 바뀌면 처음부터 다시 시작합니다. 사건기록과 같은 구조로 만들면 됩니다. 규모 2일.

### B. 학기가 바뀔 때 필요한 것

#### B-1. 반 편성 도구

지금은 반 배정을 손으로 합니다. 다음 학기 편성에서 **형제자매 분리, 성비, 인원**을
보면서 옮길 수 있는 화면이 있으면 하루가 반나절이 됩니다. 규모 3일.

#### B-2. 졸업·진급·전출입 처리

`status` 를 손으로 바꾸고 계십니다. 학년말에 137명을 한 번에 올리는 일이 곧 옵니다.
"진급 실행" 한 번으로 학년+1, 졸업 처리, 반 비우기까지. 규모 2일.

### C. 있으면 좋지만 급하지 않은 것

- **교직원 근태·연차** — 지금 당번표만 있습니다
- **시설·비품** — 교실 열쇠, 기자재 대장
- **급식 알레르기 대조** — 명부에 `allergies` 칸은 이미 있는데 쓰이지 않습니다
- **행사 참가 신청** — 지금은 문서함으로 나갑니다

### D. 권하지 않는 것

- **성적 산출·성적표** — 국제학교는 커리큘럼마다 방식이 다릅니다. 잘못 만들면
  선생님들이 결국 엑셀로 돌아갑니다. 정말 필요하면 그때 요구사항부터 받으세요
- **학부모 앱** — 앞서 보류하신 그대로가 맞습니다
- **채팅** — 토들·구글챗과 겹칩니다
