## 0. 먼저, 못 한 것

**실제 화면을 눌러보는 검증은 못 했습니다.** 브라우저로 `gia-ops.vercel.app`에 들어가면
로그인 화면에서 멈춥니다. 로그인은 제가 대신 할 수 없습니다(비밀번호·계정 자격증명은
제가 다루지 않습니다).

**필요하신 것:** 열려 있는 크롬 탭에서 한 번만 로그인해 주시면, 아래 ④의 항목들을 제가
직접 클릭·저장·재조회까지 돌려보고 결과를 다시 보고드리겠습니다. 담임 계정으로 하시거나,
개발자 계정에서 [권한 미리보기]로 교사 화면을 켜셔도 됩니다.

아래는 **코드와 논리 수준에서 실제로 돌려서 확인한 것**입니다. 추측은 추측이라고 적었습니다.

## 1. 리포트 항목 3개 (학업 / 생활 / 종합)

| 확인한 것 | 결과 |
|---|---|
| 폼·인쇄본·과거기록 보기가 모두 같은 3항목 목록을 씁니다 | ✅ `EVAL_CATEGORIES` 한 곳에서 정의, 3곳이 참조 |
| 발행 조건이 3항목으로 바뀌었습니다 | ✅ 학업·생활·종합이 모두 채워져야 발행 |
| 예전 5항목 기록이 지워지지 않습니다 | ✅ `improvement`/`participation`/`social`을 **저장에 안 보냄** → upsert가 그 칸을 건드리지 않음 |
| 예전 기록을 볼 수 있습니다 | ✅ 과거기록 보기·PDF에 "이전 서식(5항목)에 적힌 내용"으로 표시 |
| 타입 검사 / 빌드 | ✅ `tsc --noEmit` 0건, `next build` 통과 |

**추측이 아닌 이유:** 저장 payload에서 세 칸을 뺀 것이 코드에 그대로 있고, PostgREST의
upsert는 보낸 칸만 `DO UPDATE SET` 합니다.

## 2. 2주(격주) 주기

실제로 함수를 돌려 확인했습니다.

```
2026-03-02 → 2026-03-02 ~ 2026-03-15  (14일)
2026-03-08 → 2026-03-02 ~ 2026-03-15  (14일)   ← 같은 기간
2026-03-15 → 2026-03-02 ~ 2026-03-15  (14일)   ← 경계 마지막 날
2026-03-16 → 2026-03-16 ~ 2026-03-29  (14일)   ← 다음 기간으로 넘어감
2026-08-31 → 2026-08-31 ~ 2026-09-13  (14일)
2026-02-27 → 2026-02-16 ~ 2026-03-01  (14일)   ← 기준일 이전도 정상
```

- 화면 이름은 **'위클리 리포트' 그대로**입니다(요청하신 두 번째 방식).
- 리포트 창 제목 옆에 지금 기간이 뜹니다 — "8월 31일 ~ 9월 13일 (2주)".
- 격주를 한 주 밀어야 하면 `src/lib/weeklyReport/week.ts`의 `ANCHOR_MONDAY` 한 줄만
  7일 옮기면 전체가 따라옵니다.

## 3. 저장·기록 테스트 — **버그 2건 발견해서 고쳤습니다**

요청하신 "작성과 기록, 저장이 되는지"를 훑다가 나온 것들입니다. **둘 다 조용히 틀리는
종류**라, 지금까지 아무도 몰랐을 가능성이 높습니다.

### ① 같은 기간에 이어 쓰면 리포트가 두 줄로 갈라졌습니다 (심각)

저장 열쇠가 `(학생, 과목, report_date)`인데 `report_date`에 **그날 날짜**를 넣고
있었습니다. 월요일에 쓰고 수요일에 이어 쓰면 열쇠가 달라져 **새 줄**이 생깁니다.
화면은 최근 것만 보여주므로 **월요일에 쓴 글이 사라진 것처럼 보입니다.**

주 단위일 때도 있던 문제인데, 2주로 늘리면 갈라질 수 있는 날이 7일 → **14일**이 됩니다.
바꾸는 김에 안 고쳤으면 문제가 두 배가 될 자리였습니다.

**검증** — 실제와 같은 고유 제약을 건 가짜 DB에 4일에 걸쳐 이어 쓰기:

```
예전 방식 → 4줄
  2026-08-31  "1번째로 쓴 글"
  2026-09-02  "2번째로 쓴 글"
  2026-09-04  "3번째로 쓴 글"
  2026-09-09  "4번째로 쓴 글"

고친 방식 → 1줄
  2026-08-31  "4번째로 쓴 글"      ← 같은 줄을 계속 고침

기간을 넘어가면 → 2줄 (정상)
  2026-08-31  "1기 이어쓰기"
  2026-09-14  "2기 이어쓰기"

오전 8:50 / 9:10 (예전 UTC 버그 자리) → 1줄 (정상)
```

### ② 반별 작성 현황이 1,000줄에서 말없이 잘렸습니다 (심각)

`StudentReportBoard`가 **한 학기치 전체**를 상한 없이 가져오고 있었습니다. Supabase는
한 번에 돌려주는 줄 수에 상한(1,000)이 있고, 넘으면 **잘렸다는 표시 없이** 잘립니다.

한 반 15명 × 과목 8 × 기간 9 ≈ **1,000줄**. 학기 후반에 정확히 걸립니다.
잘리면 **이미 쓴 리포트가 "미작성"으로 보입니다** — 선생님은 다 썼는데 안 썼다는 화면을
보게 되고, 행정실은 독촉하게 됩니다.

고침: ① 최근 60일치만(이번 기간 + 직전 네 기간) ② 1,000줄씩 끝까지 나눠 읽기.
**통계 화면은 이미 이렇게 읽고 있었는데 여기만 빠져 있었습니다.**

## 4. 교사 메뉴 전체 점검

담임 선생님이 실제로 보는 메뉴는 다섯 개입니다.

| 메뉴 | 저장 지점 | 오류가 나면 | 코드 점검 | 클릭 확인 |
|---|---|---|---|---|
| 🏫 우리 반 개요 `/my-class` | (읽기 전용) | — | ✅ | ⏳ 로그인 필요 |
| 📝 주간 리포트 `/weekly-report/homeroom` | `wr_reports` upsert | 실패 사유를 창 안에 빨간 글씨로 표시 + "창을 닫지 마세요" 안내 | ✅ | ⏳ |
| 🚗 우리 반 픽업 `/pickup` | `shuttle_boardings` | 토스트로 알림 | ✅ | ⏳ |
| 💬 행정실 문의 `/my-class/office` | `POST /api/…` | 토스트로 알림, 쓴 글은 칸에 남음 | ✅ | ⏳ |
| ⚙️ 계정 `/account` | `app_users` | 토스트로 알림 | ✅ | ⏳ |

**"오류를 삼키는 코드"는 이 다섯 곳에는 없습니다.** 전부 실패를 사람에게 보여줍니다.
(이건 이번 주에 반복해서 나왔던 문제라 따로 훑었습니다.)

### 상한 없는 조회 전수 조사

빠르게 쌓이는 표 7개(`wr_reports`, `shuttle_boardings`, `pickup_requests` 등)에 대해
`limit`/`range`/`count` 없이 조회하는 곳을 전부 세었습니다 — **49곳**.

- 대부분은 **날짜 한 날로 묶여 있어** 자연히 200줄 안쪽입니다(오늘 하루 셔틀·픽업).
- 진짜 위험한 것은 **날짜로 안 묶인 채 계속 쌓이는** 것 하나였고, 그게 위 ②입니다. 고쳤습니다.
- 하나 남겨둡니다: `admin/dashboard`의 `wr_reports` 조회가 기간만 걸려 있어 학기가 길어지면
  **집계가 조용히 작게 나올** 수 있습니다. 관리자 화면이라 급하지 않아 보고만 드립니다.

## 5. 하원수단 칸 (백서아 사례)

백서아 같은 아이를 등록하는 방법입니다.

1. **학생 조회 → 백서아 → 🏠 하원수단 (요일별) → [입력]**
2. 다섯 요일을 이렇게 채웁니다.

| 요일 | 종류 | 시각 | 이름 |
|---|---|---|---|
| 월 | 셔틀 | | |
| 화 | 외부버스 | 1:55 | 메타프랩버스 |
| 수 | 외부버스 | 4:30 | 블루웨일버스 |
| 목 | 외부버스 | 1:55 | 메타프랩버스 |
| 금 | 외부버스 | 3:35 | 블루웨일버스 |

- 화요일을 채운 뒤 목요일 줄의 **[↑ 위와 같이]** 로 복사하면 오타가 안 납니다.
- 저장하면 **담임 선생님의 [우리 반 픽업] 화면**에 그날 수단이 아이 이름 밑에 뜹니다
  (`🏠 1:55 메타프랩버스`). 예전에는 "셔틀 미탑승"만 떠서, **무엇을 안 타는지**만 알려주고
  **무엇을 타는지**는 안 알려줬습니다.
- 셔틀 호차는 여기 안 적습니다 — 그건 [셔틀 > 탑승배정]이 정답입니다. 같은 값을 두 곳에서
  고치면 어느 쪽이 맞는지 알 수 없게 됩니다.

**⚠️ 이 기능은 새 표가 DB에 만들어져야 동작합니다** (`20260831220000_dismissal_plans.sql`).
아직 안 걸렸으면 [입력] 후 저장할 때 빨간 글씨로 그렇게 알려줍니다.

## 6. "every friday" 반복 인식

`Theo is pick up everyfriday 3:10` 이 오늘 하루 픽업으로 들어간 건은 **AI 프롬프트에 규칙이
이미 있었는데도 모델이 놓친** 경우였습니다. 그래서 규칙으로 한 번 더 보게 했습니다.

16가지로 검증, **전부 통과**:

| 문장 | 결과 |
|---|---|
| `@John Kang @Paul Lee @Rachel Bailey Theo is pick up everyfriday 3:10 !` | 금 ✅ |
| `Theo is pick up every friday 3:10` | 금 ✅ |
| `매주 금요일 3시 10분에 데리러 갈게요` | 금 ✅ |
| `금요일마다 픽업입니다` | 금 ✅ |
| `매 화요일 픽업` | 화 ✅ |
| `매주 화·목 픽업할게요` | 화·목 ✅ |
| `매일 제가 데리러 갑니다` | 월~금 ✅ |
| `She is picked up Fridays` | 금 ✅ |
| `each Monday pickup` | 월 ✅ |
| `everyday pickup` | 월~금 ✅ |
| `이번주 금요일 픽업이요` | (반복 아님) ✅ |
| `다음주 월요일 결석합니다` | (반복 아님) ✅ |
| `오늘 3시 픽업이요` | (반복 아님) ✅ |
| `매주 금요일 픽업이고, 다음주 월요일은 결석입니다` | 금만 ✅ (월이 딸려오지 않음) |
| `매주 토요일 특강` | (평일 아님, 제외) ✅ |
| `감사합니다 매주 알림 잘 받고 있어요` | (반복 아님) ✅ |

- 반복으로 읽히면 **지속 특이사항**으로 올라가고, 동시에 **"셔틀 명단에서 그 요일 체크를
  풀어주세요"** 라는 업무가 만들어집니다. 특이사항은 임시 방편이고 근본은 배정이라서입니다.
- 반복 같은데 **요일을 못 읽은 경우**(예: "앞으로 계속 제가 데리러 갈게요")는 자동 확정을
  막습니다. 기계가 정할 수 없으면 사람이 봐야 합니다.
- 픽업 인박스에 🔁 배지가 붙습니다. **이미 쌓여 있는 줄에도** 붙습니다 — 고친 규칙이 어제
  들어온 연락에는 소용없다면 담당자는 여전히 손으로 찾아야 하니까요.

## 7. 확인 부탁드릴 것

1. **크롬에서 로그인 한 번** → 위 ④의 ⏳ 항목을 제가 직접 눌러보고 결과를 보고드리겠습니다.
2. **마이그레이션 적용 여부** — 개발자 → 진단 화면에서 확인해 주세요. 8/31자 마이그레이션이
   6개 있습니다(`..120000` ~ `..220000`). 지난번에 3개가 안 걸려 있던 이유(GitHub Actions가
   안 돈 것으로 보임)를 아직 못 찾았습니다.
3. **선생님들께 안내** — 항목이 3개로 줄고 2주에 한 번으로 바뀐 것. 화면 이름은 그대로라
   말씀 안 드리면 예전처럼 매주 쓰실 수 있습니다.
