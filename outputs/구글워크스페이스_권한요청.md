# Google Workspace 권한 요청서

## 운영 앱과 구글 생태계 연동을 위한 서비스 계정 권한

요청자 강경원 (johnkang@giamicro.com) · 2026년 8월 27일

# 1. 한 줄 요약

**서비스 계정 하나에 도메인 전체 위임(Domain-Wide Delegation)을 열어주시면, 앞으로 구글 관련 연동 요청을 반복해서 드리지 않아도 됩니다.**

관리 콘솔에서 **한 번, 약 10분**이면 끝나는 작업입니다.

---

# 2. 지금 무엇이 불편한가

## 2-1. 사람이 매번 옮기고 있습니다

학교는 구글 생태계를 폭넓게 쓰고 있습니다. 그런데 운영 앱과 이어진 것은 **구글챗 하나뿐**입니다.

| 구글 서비스 | 학교에서 쓰는 용도 | 앱과의 연결 |
|---|---|---|
| 구글챗 | 직원 소통 · 출결 알림 | ✅ 자동 |
| 구글시트 | 학생 명부 · 셔틀 차량표 | ❌ CSV 복사·붙여넣기 |
| 구글폼 | 신입생 신청 · 교복 구매 · 행사 참여 | ❌ 응답 시트를 붙여넣기 |
| 구글 캘린더 | 학사일정 | ❌ 연결 없음 |
| 구글 드라이브 | 학교 문서 | ❌ 연결 없음 |
| 관리 콘솔 | 교직원 계정 | ❌ 수동 승인 |

`❌` 표시된 것들은 **담당자가 손으로 옮깁니다.** 옮기는 과정에서 빠지거나 잘못 붙는 일이 생기고, 담당자가 자리에 없으면 그날 일이 멈춥니다.

## 2-2. 지금 연결마저 개인 계정에 매달려 있습니다

구글챗 연동은 **제 개인 계정의 인증 토큰 하나**로 돌아갑니다.

```
제 계정이 비활성화되면        → 구글챗 수집이 끊깁니다
제 비밀번호를 바꾸면          → 재인증이 필요합니다
제가 학교를 떠나면            → 연동이 사라집니다
```

**이건 학교 자산이 아니라 개인에게 매인 구조입니다.** 서비스 계정으로 옮기면 담당자가 바뀌어도 끊기지 않습니다.

# 3. 요청드리는 것

## 3-1. 무엇을

Google Cloud에 만든 **서비스 계정** 하나에, Workspace 관리 콘솔에서 **필요한 권한 범위만** 등록해 주시는 것입니다.

서비스 계정은 사람이 아니라 **프로그램 전용 계정**입니다. 로그인할 수 없고, 비밀번호가 없으며, 등록된 범위 밖의 일은 할 수 없습니다.

## 3-2. 작업 순서 (관리자)

```
관리 콘솔 (admin.google.com)
  → 보안
  → 액세스 및 데이터 제어
  → API 제어
  → 도메인 전체 위임
  → 도메인 전체 위임 관리
  → 새로 추가
```

여기에 두 가지를 입력합니다.

| 항목 | 값 |
|---|---|
| 클라이언트 ID | (제가 별도로 전달드립니다 — 숫자 21자리) |
| OAuth 범위 | 아래 4-1 표의 목록 |

저장 후 반영까지 **최대 1시간**이 걸립니다.

> **참고** — 2024년 8월부터 구글은 일부 고권한 작업에 **다중 승인**을 요구합니다.
> 최고 관리자가 두 분 이상이면 다른 한 분의 승인이 추가로 필요할 수 있습니다.

# 4. 요청하는 권한 범위

## 4-1. 최소 권한 원칙으로 나눴습니다

읽기만 필요한 것은 **읽기만** 요청합니다. 쓰기가 필요한 것은 이유를 함께 적었습니다.

| # | 권한 범위 | 읽기/쓰기 | 무엇에 쓰는가 |
|---|---|---|---|
| 1 | `spreadsheets` | 읽기·쓰기 | 학생 명부·셔틀 차량표를 앱과 시트 양쪽에서 볼 수 있게. 앱에서 바뀐 내용을 시트에도 반영 |
| 2 | `forms.responses.readonly` | **읽기만** | 신입생·교복·행사 신청이 들어오면 앱으로 자동 전달 |
| 3 | `drive.readonly` | **읽기만** | 학교 문서를 앱 안에서 열람 (수정은 드라이브에서) |
| 4 | `calendar` | 읽기·쓰기 | 학사일정을 한 곳에서만 입력하면 양쪽에 반영 |
| 5 | `chat.messages.readonly` | **읽기만** | 출결 알림 수집 (지금 개인 계정으로 하던 것을 대체) |
| 6 | `admin.directory.user.readonly` | **읽기만** | 교직원 입·퇴사 시 앱 계정 자동 반영 |

**정확한 문자열** (관리 콘솔에 붙여넣으실 값)

```
https://www.googleapis.com/auth/spreadsheets,
https://www.googleapis.com/auth/forms.responses.readonly,
https://www.googleapis.com/auth/drive.readonly,
https://www.googleapis.com/auth/calendar,
https://www.googleapis.com/auth/chat.messages.readonly,
https://www.googleapis.com/auth/admin.directory.user.readonly
```

## 4-2. 요청하지 **않는** 것

안심하실 수 있도록 명시합니다.

| 권한 | 요청 안 함 | 이유 |
|---|---|---|
| Gmail 읽기·발송 | ❌ | 필요 없습니다. 이메일은 건드리지 않습니다 |
| 사용자 계정 생성·삭제 | ❌ | 계정 관리는 관리자 고유 권한으로 남깁니다 |
| 비밀번호 재설정 | ❌ | 동일 |
| 드라이브 쓰기·삭제 | ❌ | 읽기만 요청합니다. 문서를 지우거나 고칠 수 없습니다 |
| 조직 설정 변경 | ❌ | 필요 없습니다 |

> 나중에 정말 필요해지면 **그때 다시 말씀드리고 범위를 추가**하겠습니다.
> 지금 미리 넓게 열어두는 방식은 택하지 않았습니다.

# 5. 이렇게 하면 무엇이 달라지는가

## 5-1. 사라지는 수작업

| 지금 | 권한 부여 후 |
|---|---|
| 구글폼 응답을 시트에서 복사 → 앱에 붙여넣기 | 신청이 들어오면 앱에 바로 |
| 명부를 시트에서 고치고 앱에서 또 고치기 | 한 곳만 고치면 양쪽 반영 |
| 학사일정을 캘린더·앱에 각각 입력 | 한 번만 입력 |
| 문서 보려고 드라이브 왔다 갔다 | 앱 안에서 열람 |
| 신입 교직원 계정을 관리자가 수동 승인 | 자동 반영 |

## 5-2. 없어지는 취약점

```
제 개인 계정 토큰 의존       → 학교 자산인 서비스 계정으로
크롬 확장 프로그램 의존       → 담당자 PC가 꺼져 있어도 동작
```

지금 토들 수집은 **담당자 컴퓨터의 크롬 확장 프로그램**이 화면을 긁어오는 방식입니다. 컴퓨터가 꺼져 있으면 그날 연락을 통째로 놓칩니다. 구글 쪽을 서버 연동으로 바꾸면 이 취약점이 크게 줄어듭니다.

## 5-3. 반복 요청이 사라집니다

이 요청을 드리는 가장 큰 이유입니다.

```
지금 방식:  기능이 하나 늘 때마다 → 관리자께 요청 → 대기 → 설정 → 진행
권한 부여 후: 등록된 범위 안에서는 요청 없이 진행
```

**부이사장님 시간을 반복해서 빌리지 않아도 됩니다.**

# 6. 안전장치

권한을 여는 일이라 어떻게 관리할지도 함께 말씀드립니다.

| 항목 | 내용 |
|---|---|
| 취소 | 관리 콘솔에서 언제든 즉시 회수 가능합니다 |
| 감사 로그 | 서비스 계정의 모든 접근은 관리 콘솔 감사 로그에 남습니다 |
| 열쇠 보관 | 서비스 계정 키는 Vercel의 암호화된 환경변수에만 둡니다. 코드에는 넣지 않습니다 |
| 범위 확대 | 새 권한이 필요하면 반드시 별도로 요청드립니다 |
| 정기 점검 | 학기마다 실제로 쓰는 범위만 남기고 정리하겠습니다 |
