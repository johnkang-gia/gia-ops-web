### 새로 생기는 제약 — 딱 하나

**데스크톱 앱이 열려 있어야 합니다.** 닫으면 세션은 계속 돌지만 **이 컴퓨터의 파일에 손이
닿지 않습니다.**

이 저장소에서는 이게 실제로 위험한 자리가 있습니다. 배포 절차가
`빌드 → 커밋 → main push → 2~3분 대기 → staging push` 인데, 그 **대기 중에 앱을 닫으면**
뒷부분이 안 돕니다. 그러면 마이그레이션은 적용됐는데 staging 이 옛 코드인 상태로 남습니다.

→ **배포하는 동안에는 앱을 닫지 않습니다.**

## 5. 배포 절차 — 어느 쪽이든 그대로입니다

`CLAUDE.md` 3번과 같습니다.

```bash
npx tsc --noEmit                          # 먼저 타입
# CHANGELOG.md 맨 위에 ## v0.XXX.0 - YYYY-MM-DD 추가
npm run check:changelog                   # 대화 인용 검사
npm pkg set version=0.XXX.0
npm run build                             # 게이트 34개 + 빌드
git add -A && git commit -m "v0.XXX.0 — …"
git push origin main:main                 # 여기서 GitHub Actions 가 마이그레이션 적용
# 2~3분 기다린 뒤 (이 사이에 데스크톱 앱을 닫지 않습니다)
git push origin main:staging
git branch -f staging main
```

**`main` 과 `staging` push 사이에 기다리는 이유:** 마이그레이션이 먼저 적용돼야 새 코드가
찾는 칸이 DB 에 있습니다. 순서를 뒤집으면 「column does not exist」가 납니다.
