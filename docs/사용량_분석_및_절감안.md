측정일 2026-08-26 · v0.251.0 기준 · 코드베이스 실측(폴링 주기·크론 스케줄·루프 구조를 직접 읽어 계산)

## 결론 한 줄

**Vercel 함수 실행시간의 97%를 크론 3개가 씁니다.** 이 셋만 손보면 전체가 78% 줄어듭니다. Supabase는 저장·요청 모두 여유롭습니다.

### 왜 크론 3개가 압도적인가

셋 다 **외부 스케줄러가 1분마다** 부르고, 각 호출이 **함수를 25초 동안 붙잡습니다**.

```
maxDuration = 30
LOOP_BUDGET_MS = 25_000     ← 25초 동안
LOOP_INTERVAL_MS = 3~5_000  ← 3~5초마다 반복 조회
```

Vercel 무료 플랜의 Fluid Active CPU 한도(4시간)를 터뜨린 진짜 원인이 이것입니다. 화면 폴링을 아무리 줄여도 여기가 그대로면 표가 안 났던 이유입니다.

**게다가 24시간 내내, 주말에도 돕니다.**

- 셔틀 자동 도착·출발 감지 → 차가 다니는 **평일 15:30~18:30(3시간)** 에만 의미가 있습니다. 나머지 21시간은 빈 조회입니다.
- 구글챗 미러링 → 선생님이 글을 쓰는 **근무 시간**에만 의미가 있습니다. 새벽 3시에 3초마다 구글챗을 확인할 이유가 없습니다.

즉 **900시간 중 약 780시간이 아무 일도 없는 시간에 도는 헛돌기**입니다.

## 2. 절감안

### ① 매분 크론에 시간대 문지기 달기 — 효과 최대

세 크론 모두 맨 앞에서 "지금이 일할 시간인가"를 보고, 아니면 **루프에 들어가지 않고 즉시 반환**합니다.

| 크론 | 일할 시간 | 24시간 중 |
|---|---|---:|
| `shuttle-auto-arrive` | 평일 15:30~18:30 | 9% |
| `shuttle-auto-depart` | 평일 15:30~18:30 | 9% |
| `poll-chat-messages` | 평일 07:00~20:00 | 39% |

호출 수는 그대로지만(외부 스케줄러가 계속 부르므로) **함수 실행시간이 900h → 175h로 줄어듭니다.**

> 호출 자체를 없애려면 외부 스케줄러 쪽 일정을 시간대별로 나눠야 하는데, 그건 cron-job.org 설정을 손보는 일이라 앱 코드로는 못 합니다. 실행시간만 막아도 과금의 대부분은 잡힙니다.

### ② 안내보드·도착체크를 하원 시간대 밖에서 완전히 멈추기

지금은 하원 시간대 밖에도 60초마다 돕니다. 그런데 그 시간에는 **화면 앞에 아무도 없습니다**(하원용 화면입니다). 하원 시간대(평일 3시간)에만 돌고 나머지는 멈추면 됩니다.

- 월 234,000 → 79,200 (66% 감소)
- 아침에 스스로 깨어나야 하므로 완전 정지가 아니라 아주 긴 주기(1시간)로 두고, 하원 시작 시각을 넘겨서 자지 않게 합니다. 운영 대시보드에 이미 적용한 방식과 같습니다.

### ③ GPS는 Distance 설정이 유일한 안전장치

35대로 늘릴 때 **기사님 앱 `Distance = 30m`가 없으면 월 302만 호출**로 Pro 포함량(100만)을 3배 초과합니다. 이건 절감이 아니라 필수입니다.

| | 월 호출 |
|---|---:|
| Distance 0 (현재 설정) × 35대 | **3,024,000** ❌ |
| Distance 30m × 35대 | **184,800** ✅ |

정류장 학습은 v0.244에서 '기록이 비는 모습'도 인식하도록 고쳐뒀으므로 Distance를 걸어도 깨지지 않습니다.

**저장은 몇 년을 굴려도 여유롭습니다.** GPS 원본이 전체 증가량의 84%인데 30일 보관이라 쌓이지 않고, 실제로 나중에 보는 것은 거기서 뽑아낸 요약(정류장 도착·정차 관측·운행 이벤트)입니다.

### 주의해서 지켜볼 것

1. **위클리 리포트는 영구 보관**입니다. 연 20MB씩 계속 쌓입니다(6년이면 120MB). 학교의 실제 기록이라 지우면 안 되고, 지금 속도면 문제도 없습니다. 학생이 3배로 늘면 그때 학기별 아카이브를 검토합니다.
2. **GPS 35대는 저장이 아니라 호출이 문제**입니다. Distance 설정 없이 배포하면 그날 바로 한도를 넘깁니다.
3. **크론을 새로 추가할 때는 "몇 초 동안 도는가"를 먼저 봅니다.** 매분 × 25초 루프 하나가 화면 폴링 수십 개보다 무겁습니다.

## 4. 권장 순서

1. **크론 3종 시간대 문지기** — 실행시간 78% 감소. 가장 크고 위험이 없습니다.
2. **기사님 앱 `Distance = 30m`** — 35대 배포 전 필수. 안내문 인쇄본에 이미 반영돼 있습니다.
3. **안내보드·도착체크 야간 정지** — 부수적이지만 같은 방식이라 함께 하면 간단합니다.

Supabase는 지금 손댈 것이 없습니다. 다음에 볼 시점은 학생 수가 크게 늘거나 등원 GPS까지 확대할 때입니다.
