# 학생 하루 보드 — 설계 제안

> 「오늘 이 아이에게 평소와 다른 무슨 일이 있는가」를 **학생 하나에 한 줄**로 모으는 보드.
>
> 지금: 백서아의 픽업은 [오늘 변동사항]에, 약 이야기는 [학생 특이사항]에, 원문은 [픽업
> 인박스]에, 하원은 [하원 체크표]에 있습니다. 네 곳을 눈으로 이어야 「백서아 = 13:55 픽업 +
> 1시 이후 약」이 됩니다.
>
> 목표: 그 이어붙이는 일을 **코드가 한 번** 하고, 화면은 결과만 그립니다.

---

## 1. 지금 자료가 어디에 있나 (실측)

| 무엇 | 표 | 학생 번호를 들고 있나 | 지금 읽는 함수 |
|---|---|---|---|
| 픽업 · 학부모 문의 | `pickup_requests` (`kind`='픽업'/'문의') | **있음** (`student_id`) + `channel_label`·`channel_id` | `loadTodayPickups` |
| 결석 · 지각 · 앞날 예정 | `attendance_entries` | **있음** | `loadActiveEntries` · `loadUpcomingEntries` |
| 하원수단 (학원차·보호자) | `student_dismissal_plans` | **있음** | `loadDismissalForDay` |
| 셔틀 탑승 · 오늘 체크 | `shuttle_boardings` ← `shuttle_assignments` | 배정을 거쳐 **있음** | `effectiveRouteId` 계열 |
| 기간 특이사항 (결석기간·셔틀제외) | `shuttle_persistent_notes` | **있음** | 체크표 사이드바 |
| 학생 특이사항 (약·결제·준비물) | `student_day_notes` | **있음** | `/api/student-notes` |
| 업무 | `tasks` | **없음** ← 구멍 | 이름 `ilike` 검색 |
| 구글챗 원문 | `google_chat_mirror_messages` | **없음** (본문 글자뿐) | 출결내역 위젯이 그때그때 대조 |

**좋은 소식**: 여덟 갈래 중 여섯이 이미 `student_id` 를 들고 있습니다. 새로 이어붙일 것이
많지 않습니다.

**나쁜 소식 둘**:

- `tasks` 에 학생 번호가 없습니다. 학생 프로필 화면은 지금 `ilike '%이름%'` 로 찾습니다 —
  「김재이」로 검색하면 김재이 셋의 업무가 전부 나오고, 「이준」은 이준서·이준우·이준혁에
  모두 걸립니다.
- 구글챗 원문은 표에 이름만 글자로 있습니다. 이름→학생 판정(`matchStudent`)을 **읽을 때마다**
  다시 돌립니다.

## 2. 첫 번째 결정 — 새 표를 만들지 않습니다

「모아 둔 표」(`student_day_board` 같은 것)를 하나 만들고 싶어집니다. 하지 않습니다.

- 같은 사실이 두 곳에 적힙니다. 픽업을 취소했는데 모아둔 표에 남으면 보드는 계속 「픽업」이라
  말합니다 — 화면에는 오류가 아니라 **그냥 다른 답**으로 보입니다.
- 이 저장소가 이미 그 실수를 했습니다. 「하원수단 → 오늘 픽업」이 한 방향으로 흐르는데 화면이
  출발점과 도착점을 나란히 보여줘서, 백서아·황이안이 두 번 세어졌습니다(`pickups.ts` 주석).
- CLAUDE.md §2-12 의 「계산은 저장하지 않습니다」와 같은 이유입니다.

**대신 읽는 자리를 하나 만듭니다.** `src/lib/studentDay.ts` — 여러 표에서 읽어 학생 번호로
묶어 돌려주는 **순수 조립 함수**. 자료는 각자 제 표에 그대로 있고, 보드는 그때그때 봅니다.

```
                    ┌──────────────────────────────────────┐
  pickup_requests ─→│                                      │
  attendance_entries│   loadStudentDay(supabase, {날짜,부서}) │→ StudentDay[]
  dismissal_plans ─→│   · 학생 번호로 묶는다                  │
  shuttle_boardings │   · 평소와 다른 것만 남긴다             │
  persistent_notes ─│   · 시각순으로 세운다                   │
  student_day_notes │                                      │
  tasks ───────────→└──────────────────────────────────────┘
                              ↓             ↓            ↓
                        업무보드       중앙 대시보드   학생 프로필
```

## 3. 두 번째 결정 — 「평소와 다른 것」만 올라옵니다

이 보드의 정의를 한 줄로 못박습니다. **오늘 이 아이에게 평소와 다른 점이 있는가.**

이 줄이 없으면 보드는 첫날부터 139줄이 됩니다 — 셔틀을 타는 아이 전원이 매일 올라오니까요.
139줄짜리 보드는 아무도 안 봅니다.

| 올라옴 | 안 올라옴 |
|---|---|
| 오늘 픽업 (평소엔 셔틀) | 늘 타던 호차를 오늘도 탐 |
| 결석 · 지각 · 조퇴 | 평소처럼 등교 |
| 약 · 결제 · 준비물 (특이사항) | — |
| 오늘만 노선 이동 | 계속 이동(이미 그게 평소) |
| 답 안 한 학부모 문의 | 이미 답한 문의 |
| 확인대기 인박스 (누구인지 모르는 건) | 확정된 건 |
| 마감이 오늘인 그 아이 업무 | 마감이 먼 업무 |

「평소」의 기준은 이미 코드에 있습니다 — `student_dismissal_plans` 의 요일별 계획과
`shuttle_assignments` 의 배정. 그것과 **다른** 줄만 올립니다.

## 4. 자료 모양

```ts
/** 한 아이의 하루. 화면은 이것만 받습니다. */
export type StudentDay = {
  studentId: string;
  name: string;            // 명부의 지금 이름 (적힌 이름이 아니라)
  grade: string | null;
  className: string | null;
  department: "초등부" | "중고등부" | ...;
  /** 시각순. 시각 없는 것은 뒤. */
  items: DayItem[];
  /** 가장 이른 시각. 보드를 세우는 열쇠. */
  firstTime: string | null;
  /** 하나라도 사람이 손대야 하면 true. 화면이 색을 정하는 데 씁니다. */
  needsAction: boolean;
};

export type DayItem = {
  /** 어느 갈래인가. 색·아이콘이 여기서 나옵니다. */
  kind: "픽업" | "결석" | "지각" | "하원변경" | "약" | "결제" | "준비물" | "건강" | "문의" | "업무" | "기타";
  /** 몇 시. 없으면 「오늘 중에」. */
  at: string | null;
  /** 한 줄 요약. 「13:55 어머니 픽업」·「1시 이후 감기약」 */
  text: string;
  /**
   * **어디서 왔는가.** 「왜 이 줄이 떴지」에 답하는 값입니다. 이게 없으면 사람은
   * 보드를 못 믿고 결국 원래 화면 네 개를 다시 엽니다.
   */
  from: { table: string; id: string; screen: string };
  /** 아직 사람이 한 번 봐야 하는가(확인대기·미답 문의). */
  pending: boolean;
};
```

화면에 그려지는 모양:

```
백서아  2학년 G2C                                   ⚠ 확인 2
  🚗 13:55  어머니 픽업                        (토들 · 확정)
  💊 13:00~ 감기약 한 봉                        (특이사항 · 김선생)
  💬        "오늘 좀 늦을 수도 있어요"           (문의 · 아직 답 안 함)

김재이(G2A)  2학년 G2A
  🏥 결석    09/16 ~ 09/23 · 입원                (출결 · 등록됨)
```

## 5. 세 번째 결정 — 학생 하나로 묶는 열쇠

**학생 번호입니다. 이름이 아닙니다.** 이 저장소에서 다섯 번 난 사고의 자리입니다
(CLAUDE.md §2-4-1). 이름으로 묶으면 김재이 셋이 한 줄이 되고, 화면에는 오류가 아니라
「김재이 한 명이 픽업 + 약 + 결석」으로 보입니다.

### 번호가 없는 줄은 어떻게 하나

**따로 세웁니다.** 보드 맨 아래 「누구인지 모르는 것」 칸입니다.

```
❓ 누구인지 아직 모릅니다 · 3건
  "재이 오늘 일찍 갈게요"   G2_Jay_Office 채널   [🔎 학생 연결]
```

억지로 붙이지 않습니다. 「재이」는 김재이·심재이·유재이 셋의 표기이고, 그중 한 명에 붙이면
**나머지 둘의 보호자는 아무 소식도 못 받습니다.** 화면에 「모른다」가 떠 있어야 사람이 눌러
고칩니다.

### 번호를 찾는 순서 (이미 있는 규칙을 그대로)

1. 표에 `student_id` 가 있으면 그것 (여섯 갈래가 여기 해당)
2. 토들 채널 연결 — `toddle_channel_students` (학기 초에 사람이 한 번 확인한 것)
3. 채널 이름 파싱 — `parseChannelLabel` (`G2_Reina Park_Office` → 학년+이름)
4. 사람이 가르친 별칭 — `attendance_learning_rules` (「마야 = 김마야」)
5. 이름 대조 — `matchStudent` (생일 → 반 → 학년 순으로 좁힘)
6. **못 좁히면 여기서 멈춥니다.** 「확인 필요」로 내려갑니다.

전부 이미 있는 함수입니다. 보드는 새 규칙을 만들지 않고 **부르기만** 합니다.

## 6. `tasks` 의 구멍을 메우는 법

업무만 학생 번호가 없습니다. 지금은 이름 `ilike` 라 동명이인이 섞입니다.

**제안: `task_students` 딸림표.** `tasks` 에 칸을 하나 붙이지 않는 이유는 한 업무가
여러 아이에 걸리기 때문입니다(「G2 교재 배부」는 스무 명).

```sql
create table task_students (
  task_id uuid references tasks(id) on delete cascade,
  student_id uuid references wr_students(id) on delete cascade,
  primary key (task_id, student_id)
);
```

- 업무 등록 창에 **검색형 학생 고르개**(`StudentSelect`)를 하나 답니다. 선택입니다 —
  대부분의 업무는 특정 아이와 상관없습니다.
- 옛 업무는 **백필하지 않습니다.** 이름으로 짐작해 넣으면 그 순간 틀린 연결이 영구히
  남습니다. 앞으로 등록되는 것부터 붙습니다.
- 이름 `ilike` 검색은 **학생 프로필에만** 남깁니다(「혹시 이 이름이 나온 업무」 찾기용,
  「이 아이의 업무」가 아님을 화면이 적습니다). 보드에는 안 씁니다.

## 7. 화면 셋

### ① 업무보드 — 적고 고치는 자리 (왼쪽 아래, 지금의 [학생 특이사항] 확장)

지금 그 칸은 `student_day_notes` 만 보여줍니다. 같은 자리에 **전부**를 올립니다.

- 위: 지금처럼 적는 폼 (학생 검색 · 종류 · 시각 · 내용)
- 아래: **학생별로 접힌 목록.** 한 아이에 여러 건이면 한 덩어리.
- 맨 아래: 「❓ 누구인지 모릅니다」 — 눌러서 학생 연결
- 필터 한 줄: `오늘 / 앞날 / 확인 필요만`

### ② 중앙 대시보드 — 보는 자리 (오른쪽 「오늘 변동사항」 자리를 이걸로 교체)

지금 「오늘 변동사항」은 픽업·결석·지각·예정을 갈래별로 나눠 보여줍니다. 그걸 **학생별**로
바꿉니다 — 앞에 선 사람이 하는 질문은 「누가 오늘 뭐가 다른가」이지 「결석이 몇 명인가」가
아닙니다.

- 스크롤이 없으므로 **행 수를 못박고**(예: 12명) 넘치면 「외 N명」
- 시각이 있는 건이 먼저 (움직여야 하는 것)
- 5분 전 알람은 지금 방식 그대로 — 이미 한 목록입니다
- **시간표를 안 가립니다** (v0.597.0 에서 정한 규칙)

### ③ 학생 프로필 — 한 아이의 하루 (`/students/[id]`)

같은 함수를 한 명으로 좁혀 부릅니다. 지금 이 화면이 하는 이름 `ilike` 짜깁기를 대체합니다.

## 8. 실행 순서 (각 단계가 그 자체로 쓸모 있게)

| 단계 | 무엇 | 왜 이 순서인가 | 크기 |
|---|---|---|---|
| **1** | `src/lib/studentDay.ts` — 조립 함수 + 순수 부분 시험 | 화면 없이도 시험할 수 있습니다. 여기가 틀리면 나머지가 전부 틀립니다 | 중 |
| **2** | `/api/student-day` 창구 (날짜·부서) | 한 자리에서 읽어 세 화면이 나눠 씁니다 | 소 |
| **3** | 업무보드 칸 교체 | 적는 자리라 잘못 나오면 바로 보입니다. **여기서 먼저 믿을 수 있게** 만듭니다 | 중 |
| **4** | 중앙 대시보드 「오늘 변동사항」 교체 | 3에서 검증된 뒤에 큰 모니터로 | 중 |
| **5** | `task_students` + 업무 등록 창에 학생 고르개 | 구멍 메우기. 앞의 넷과 독립이라 언제 해도 됩니다 | 소 |
| **6** | 학생 프로필의 `ilike` 짜깁기 걷어내기 | 마지막. 급하지 않습니다 | 소 |

**1·2·3 까지만 해도 쓸 만합니다.** 4를 안 해도 업무보드에서 전부 보입니다.

## 9. 미리 정해둘 것들 (안 정하면 나중에 화면마다 달라집니다)

| 물음 | 제안 | 이유 |
|---|---|---|
| 하루가 언제 바뀌나 | `boardDay.ts` 의 기준 그대로 (아침 8시) | 중앙 대시보드는 밤새 켜져 있습니다. 자정에 바뀌면 새벽에 화면이 비어 아무도 안 봅니다 |
| 부서를 가르나 | 가릅니다 | 초등부 모니터에 중고등부 아이가 뜨면 앞에 선 사람이 할 일이 없습니다 |
| 앞날은 며칠 | 오늘 + 7일, 앞날은 접어서 | 이 칸은 「오늘」이 주인공입니다 |
| 완료 체크가 있나 | **없습니다** | 앞서 정한 대로 목록만. 픽업·출결은 각자 제 화면에서 처리되고, 그것이 사라지면 보드에서도 사라집니다 |
| 실시간인가 | 업무보드 60초 · 대시보드는 지금의 번호 문지기 | 표를 여덟 개 듣는 구독은 비쌉니다. 이 보드에서 1분은 견딜 만합니다 |
| 조회 비용 | `board_revisions` 문지기를 그대로 탑니다 | 안 바뀌면 여덟 표를 아예 안 읽습니다 |

## 10. 안 하기로 한 것들

- **AI 요약**. 「백서아 오늘 픽업이고 약 챙겨야 함」을 문장으로 만들어주는 것. 재료가 이미
  짧은 한 줄씩이라 얻는 것이 없고, AI가 한 줄을 빠뜨려도 **오류가 아니라 그냥 없는 것**으로
  보입니다.
- **모아둔 표**(§2). 같은 사실을 두 곳에 적는 순간 어긋납니다.
- **옛 업무 이름 백필**(§6). 틀린 연결이 영구히 남습니다.
- **셔틀 탑승 전원 표시**(§3). 139줄짜리 보드는 아무도 안 봅니다.
- **학부모에게 보여주기**. 이 보드는 교직원이 오늘 움직이기 위한 것이고, 「확인 필요」·
  「누구인지 모름」 같은 내부 상태가 그대로 보입니다.

## 11. 무엇이 좋아지나 (측정 가능한 것으로)

- 백서아를 알려면 지금 화면 **네 개** → **한 곳**
- 동명이인이 한 줄로 합쳐지는 일: 지금 학생 프로필 업무 검색에서 **일어남** → 번호로 묶어
  **없음**
