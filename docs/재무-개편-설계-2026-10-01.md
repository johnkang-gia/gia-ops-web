# 재무 개편 설계 — 학생 원장 하나, 창 하나

2026-10-01. 새 단추를 또 붙이지 않고, **지금 있는 표 위에** 돈이 생길 수 있는 모든 경우를
한 가지 방식으로 적게 하는 설계입니다. 학교 수납 시스템(FACTS · Blackbaud Tuition 류의
**학생 원장** 방식)과 일반 회계(계정과목 · 조정 · 기간 마감)의 표준 구조를 참고했고, 노션
「학교 예산 관리」 템플릿의 **예산 ↔ 집행 ↔ 잔액 자동 계산** 틀을 수입 쪽에 그대로 썼습니다.

---

## 0. 지금 무엇이 문제인가 — 실제 사례로

### 황이안 (2026-10-01 현재 자료)

| | |
|---|---|
| 신청한 학비 | 방과후 5일반 450,000 · Learning Management & Assessment Fee 300,000 |
| 청구서 | 2026-0139 **75만 전체** → 취소 · 2026-0170 (9/27) 방과후 45만 **이미받음** · 2026-0169 (9/28) 방과후 45만 **이미받음** |
| 입금 | 45만 × 2 (둘 다 「이미받음」, 올톡페이) |
| 30만은 | **청구서 없음** |

세 가지가 겹쳐 있습니다.

1. **「이미 받음」을 두 번 눌러 같은 항목이 두 장 됐습니다.** 막는 것이 없었습니다.
2. **남은 30만을 발행할 단추가 없습니다.** 표는 「남음」 표시를 띄우는데 그 줄에는 발행 단추가
   없습니다 - 청구서가 한 장이라도 있으면 단추가 사라지도록 되어 있습니다.
3. **입금이 항목이 아니라 청구서에 붙습니다.** 그래서 「45만은 받았고 30만은 안 받았다」를
   적을 자리가 처음부터 없었고, 그걸 적으려고 「이미 받음」이 청구서를 만드는 우회로가 생겼습니다.

### 그 밖에 적을 자리가 없는 돈

| 경우 | 지금 |
|---|---|
| 큰 돈을 먼저 내고 거기서 깎아 달라 | **넣을 자리가 없음.** `invoice_id = null` 이면 자동 충당은 되는데, 그런 줄을 **만드는 화면이 없습니다** |
| 실수로 두 번 냈는데 환불 말고 다음 청구에서 빼 달라 | 입금 창이 청구액 넘는 금액을 **거절**합니다. 남은 돈이 어디에도 안 적힙니다 |
| 감면·면제·대손 처리 | 할인 규칙으로만 가능. 「이 장에서 3만원 깎아줌」 같은 **한 번짜리 조정**이 없습니다 |
| 학부모에게 주는 영수증 | 현금영수증(국세청) 화면은 있는데, 학교 양식의 영수증은 없습니다 |
| 올해 얼마 걷힐 예정이고 얼마 걷혔나 | 월별 합계는 있는데 **계획 대비**가 없습니다 |

### 뿌리

돈을 적는 창이 넷(이미받음 · 결제체크 · 환불 · 선입금)이고 저마다 다른 질문을 합니다. 사람은
「돈을 받았다」는 한 가지 사실을 적고 싶은데, 어느 창을 열어야 하는지부터 골라야 합니다.
창마다 할 수 있는 것이 달라서 안 되는 경우가 생기고, 그때마다 창이 하나 더 생겼습니다.

## 1. 참고한 체계 — 표준 수납 회계가 어떻게 생겼나

학교 수납 시스템은 어디나 같은 뼈대입니다. 지금 앱에 **이미 있는 것**과 **없는 것**을 나눕니다.

| 표준 개념 | 뜻 | 지금 앱 | 상태 |
|---|---|---|---|
| **계정과목** (Chart of Accounts) | 돈의 종류. 학비·방과후·교복·교재·셔틀… | `fee_categories` · `fee_plans`(학비) · `fee_items`(학비외) | 있음. 둘로 갈라져 있지만 분류는 `fee_categories` 하나 |
| **요금표** (Fee Schedule) | 항목별 기준금액 · 납부 옵션 · 할인 규칙 | `fee_plans` + `fee_payment_options` + `fee_discounts` | 있음 |
| **학생 원장** (Student Ledger) | 학생 한 명의 차변(청구)·대변(입금·조정) 흐름과 잔액 | 청구서 + 입금을 읽어 **그때그때 계산**(`settlement.ts`) · 화면 `/finance/statement/[id]` | 있음. 다만 **조정** 줄이 없음 |
| **청구** (Charge / Invoice) | 원장에 차변을 세우는 문서 | `invoices` + `invoice_lines` | 있음 |
| **입금** (Payment) | 대변. 어느 청구에 붙었는지 | `payments.invoice_id` | 있음 |
| **미적용 대변** (Unapplied Credit) | 어느 청구에도 안 붙은 입금. 다음 청구에 자동 적용 | `payments.invoice_id = null` + `prepaidApply.ts` | 있음. **만드는 창이 없음** |
| **조정** (Adjustment) | 감면·면제·대손·정정. 입금이 아닌데 잔액을 줄이는 줄 | 없음 (할인 규칙으로 우회) | **없음** |
| **환불** (Refund) | 돈을 돌려줌 | `payments.kind = 'refund'` | 있음 |
| **영수증** (Receipt) | 입금에 대한 증빙 문서, 번호 있음 | 현금영수증(국세청)만 | **없음** |
| **미수 연령** (Aging) | 얼마나 오래 밀렸나 | `agingBucket()` · `/finance/unpaid` | 있음 |
| **기간 마감** (Period Close) | 닫힌 달은 못 고침 | `finance_month_closes` + 트리거 | 있음 |
| **예산 대 실적** (Budget vs Actual) | 받기로 한 금액 vs 받은 금액 | 없음 | **없음** |
| **대사** (Reconciliation) | 통장과 장부 맞추기 | `payment_imports` | 있음 (은행 양식만) |

없는 것 넷(조정 · 영수증 · 예산 대 실적 · 창 하나)만 더하면 표준 체계가 됩니다. **표를 새로
세우지 않고** 더할 수 있습니다 - 아래 §4.

## 2. 원칙 — 바뀌지 않는 것

이미 잘 되어 있는 것은 그대로 둡니다.

- **금액은 두 곳에 있을 수 없고**(트리거) **계산은 저장하지 않습니다**(`settlement.ts`).
- **학비와 학비외는 청구서를 따로 냅니다.** 납기와 미납 이월이 다릅니다.
- 청구서는 **지우지 않고 취소**합니다. 입금의 출처(`origin`)는 넣은 뒤 못 바꿉니다.
- 닫힌 달은 못 고칩니다.

새로 세우는 것은 하나입니다.

> **학생 한 명 = 원장 하나.** 차변(청구) − 대변(입금 · 조정) = 잔액.
> 청구서에 안 붙은 입금은 전부 **예치금**이고, 다음 청구서가 나올 때 저절로 깎입니다.

「선입금」·「과납」·「취소로 떼어낸 돈」·「미리 낸 큰 돈」·「두 번 낸 돈」은 전부 **같은 것**입니다 -
그 학생 원장에 있는, 아직 어느 청구서에도 안 붙은 돈. 이름을 하나로 합니다: **예치금.** 어디서
왔는지는 `origin` 에 남깁니다(미리받음 · 과납 · 취소떼어냄 · 주인못찾음). 학비·학비외 구분 없이
**한 통**입니다 - 학부모가 낸 돈은 학생 원장의 돈이지 학비용·교복용이 따로 있지 않습니다.

## 3. 창 하나 — 「학생 금전 창」

학생 이름을 누르면 어디서든 같은 창이 뜹니다(학비 표 · 학비외 표 · 수납 · 미납 · 학생 검색).
원장을 보여주고, 원장에 줄을 더하는 단추 **셋**뿐입니다.

```
┌ 황이안 (G2C) ───────────────────────────── 예치금 0 · 미납 300,000 · 올해 받을 돈 825,000 ┐
│                                                                                          │
│ 받을 돈 (요금표에서)                       원장 (최근부터)                                   │
│ ☑ 방과후 5일반          450,000  0170 ✓    09-27  입금  올톡페이          −450,000  → 0170   │
│ ☐ LMA Fee (연 1회)      300,000  남음      09-27  청구  2026-0170 방과후   +450,000          │
│ ☐ 교복 A 티셔츠          30,000  0164 ✓    08-27  입금  올톡페이           −75,000  → 0164   │
│ ☐ 교복 B 맨투맨          45,000  0164 ✓    08-27  청구  2026-0164 교복     +75,000          │
│                                                                           잔액 300,000     │
│ [청구서 만들기]  [입금 기록]  [예치금·조정]                      🖨 청구서 · 📄 영수증 · 원장 인쇄 │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

| 단추 | 무엇을 하나 | 지금의 어떤 창을 대신하나 |
|---|---|---|
| **청구서 만들기** | 체크한 항목만 담아 발행. **이미 담긴 항목은 회색이고 체크가 안 됩니다.** 학비와 학비외가 섞여 있으면 두 장이 나갑니다. 예치금이 있으면 바로 깎입니다 | 학비 발행 · 학비외 발행 · 남은 항목 발행 |
| **입금 기록** | 날짜·금액·수단. **어느 청구서에 붙일지는 창이 정합니다** - 오래된 미납부터. 청구서보다 많이 받았으면 **남는 돈은 예치금**으로. 청구서가 아직 없는 항목을 받았으면 「받은 항목」을 체크하게 하고, 그 항목의 청구서를 받은 날짜로 만들어 붙입니다(지금의 「이미 받음」) | 이미 받음 · 결제 체크 · 수납 입력 |
| **예치금 · 조정** | 예치금 넣기(청구서 없이 미리 받은 돈) · 조정(이 장에서 ○○원 감면 - 이유 필수) · 환불(예치금을 돌려줌) | 선입금 · 환불 · (없던 것) 조정 |

영수증(📄)은 **청구서와 같은 양식**에 제목만 「영수증」이고, 그 장에 붙은 입금의 날짜·수단·
영수증 번호가 적힙니다. 완납된 장에서만 뜹니다. 원장 인쇄는 거래내역 화면(`/finance/statement`)
그대로입니다.

### 이 창 하나로 다섯 경우가 어떻게 되나

| 경우 | 하는 일 |
|---|---|
| ① 45만만 받았고 30만은 아직 (황이안) | 입금 기록 → 받은 항목에 「방과후」만 체크 → 45만 청구서가 9/27 로 만들어지고 입금이 붙음. LMA 30만은 받을 돈에 「남음」, [청구서 만들기]에서 그것만 체크해 보냄. **두 번 누르면 두 번째는 막힘** |
| ② 큰 돈을 먼저 | 예치금 넣기 → 100만. 그 뒤 청구서마다 저절로 깎이고 창 머리의 「예치금」이 줄어듦 |
| ③ 두 번 냈는데 다음에서 빼 달라 | 입금 기록 → 45만 또 넣음 → 「이 장은 완납입니다. 넘는 450,000 을 예치금으로 둘까요」 → 예 |
| ④ 교장 상담으로 3만원 깎아주기로 | 조정 → −30,000 · 이유 「○○ 상담 감면」. 할인 규칙을 새로 만들지 않음 |
| ⑤ 돌려드려야 함 | 예치금 줄에서 환불 → 돌려준 날·수단 적음. 원장에 −로 남음 |

## 4. 자료는 어떻게 바뀌나 — 표 없이 칸·뷰·값만

| 무엇 | 왜 |
|---|---|
| `payments.origin` 값 추가: `미리받음` · `과납` · `조정` · `환불` | 예치금이 어디서 왔는지, 입금이 아닌 조정인지. 이미 있는 칸이고 불변 |
| `payments.kind = 'adjustment'` | 조정은 돈이 안 들어온 대변. 월별 「받은 돈」 합계에서 빼고 셉니다 - 섞으면 현금 합이 틀립니다 |
| `student_balance` 뷰: 학생별 미납 합 · 예치금 합 · 올해 청구 합 | 창 머리와 학생 검색이 같은 숫자를 봅니다. 저장 안 하고 그때그때 셉니다. `security_invoker` + `revoke anon` |
| `invoices_tuition_scope_month_uniq` 유일 색인 | 같은 학생·학기·청구월·항목 범위의 학비 청구서는 「발행」 한 장. **완료(1단계)** |
| 영수증 번호 `payments.receipt_no` + `next_receipt_no()` | 청구서 번호와 같은 방식. 뽑을 때 번호를 받고 다시는 안 바뀜 |
| 예산 대 실적: `fee_plans.expected_count`(예상 신청 수) | 「받기로 한 돈」 = 항목 × 예상 수. 월별 화면에 「계획 / 청구 / 수납 / 잔액」 네 칸 - 노션 템플릿의 현액·사용액·잔액과 같은 틀 |

지금 선입금 자동 충당(`prepaidApply.ts`)과 정산(`settlement.ts`)은 그대로 씁니다. 창은 이 둘을
부르기만 합니다. 조정은 `settlement` 이 입금과 똑같이 잔액에서 빼되, 월별 수납 합계는 `kind` 로
갈라 셉니다.

## 6. 일부러 안 하는 것

- **항목별 입금 기록**(45만 중 30만은 이 항목에…)은 안 만듭니다. 입금을 쪼개 적어야 하고, 학부모는
  그렇게 안 냅니다. 「어느 항목을 받았나」는 **청구서를 항목 단위로 만드는 것**으로 답합니다.
- **복식부기 분개장**은 안 만듭니다. 받는 돈만 다루는 수납 장부에는 학생 원장(차변·대변·잔액)이
  곧 분개장입니다. 지출(학교가 쓰는 돈)까지 담게 되면 그때 계정과목을 자산·부채·수익·비용으로
  넓힙니다 - 노션 템플릿이 다루는 영역이고, 지금 앱의 범위 밖입니다.
- **학비와 학비외를 한 장에** 담지 않습니다. 이월 규칙이 갈립니다.
- 올톡페이 결제 결과 **자동 수신**은 안 합니다(공개 API 없음). 결제내역 엑셀 가져오기는 4단계 뒤.
